Continue the incremental Crystal port of TAWB in /home/bmmcginty/git/tawb.

Goal
- Reimplement TAWB as a genuinely static Linux executable while preserving the JavaScript implementation as the behavioral reference.
- Run the existing Node specifications against both JavaScript and Crystal rather than creating a separate handwritten specification suite where practical.
- Browsers, Lynx, and xvfb-run remain external runtime dependencies; the TAWB artifact itself must have no ELF interpreter, no DT_NEEDED entries, and no extracted secondary runtime.
- Crystal is the chosen native language.

Established product decisions
- --dump and --keyboard are flags, not front ends.
- Front ends are default, lynx, and edb, selected by --front-end / TAWB_FRONT_END.
- --front-end edb rejects --dump and --keyboard.
- --keyboard and --dump are mutually exclusive.
- Lynx preferences are not ordinary main CLI/settings options.
- Lynx configuration import policy:
  - If keys-lynx.json is absent, import Lynx and write TAWB's files.
  - --lynx-reimport explicitly overwrites TAWB's copy.
  - Otherwise do not execute Lynx or read its config.
  - A Lynx --dump is read-only and must not import or write configuration.
- Environment variables are for deployment/wrapper concerns, not ordinary preferences.
- Alternate screen is default; --no-alt-screen opts out.
- Browsers must remain ordinary headed browsers, using xvfb-run when DISPLAY is absent.

Initial Firefox foundation
- crystal/src/tawb/bidi.cr now has:
  - JSON command/reply routing over the static WebSocket transport;
  - event queuing;
  - recursive WebDriver BiDi tagged-value decoding for scalars, arrays, sets, objects, maps, and remote references.
- Shared BiDi remote-value tests run against JavaScript and Crystal.
- Do not shortcut Firefox startup. The JavaScript implementation deliberately:
  - starts an ordinary Firefox;
  - uses Marionette chrome-context code to clear the automation state that drives navigator.webdriver;
  - keeps Marionette available to release stranded BiDi sessions;
  - uses a local broker because Firefox allows only one BiDi session per browser.
- Read src/firefox.js, src/driver_firefox.js, src/bidi.js, and src/broker.js carefully before implementing Firefox. Preserve these semantics rather than merely launching Firefox with automation enabled.

Important current limitations
- Native interactive terminal reading is not ported.
- Native Firefox browser launch/session lifecycle and Firefox dump are not ported.
- Native edb is not ported.
- Firefox is the next major browser concern, but it must include the existing Marionette automation-state behavior and broker/session ownership semantics.
- The native Lynx dump currently uses width 80, matching JavaScript when stdout is piped; terminal-width discovery for direct TTY output has not been ported.
- Browsers and xvfb-run remain external by design.
