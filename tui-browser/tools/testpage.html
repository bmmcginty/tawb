Every control here reports what it received, at the bottom of the page, including whether the browser considered the event trusted. Nothing on this page talks to the network.

1. Native select, with a prefix collision

"United States" is a strict prefix of two other entries, and the longer ones come first. Type-ahead cannot express "I meant the short one".

2. Native select, long enough that position matters

Sixty entries, so the chosen one has to be scrolled to rather than merely found.

3. Custom combobox — click only, deliberately

Built the way a framework builds one: the button carries aria-expanded and aria-controls, the options are list items with click handlers, and no key handler exists anywhere on it. Sending keystrokes at it does nothing at all, which is the point.

4. Menu button whose menu is portaled to the end of the document

The hard case. When this opens, the menu is appended to the very end of <body> — nowhere near the button. In a line list it appears hundreds of lines below wherever the reader is standing, so "activate it and re-read the page" finds nothing. aria-controls is the only thread back to it.

5. Two controls with the same accessible name

Both are called "Open". Resolving a line by role and name reaches the first one whichever was pressed; resolving it by the node the tree recorded reaches the right one. The log below says which fired.

6. Native disclosure

A <details> element carries its open state in the DOM rather than in aria-expanded, so a reader that only reads the attribute has nothing to report here. Known gap, kept on the page on purpose.
